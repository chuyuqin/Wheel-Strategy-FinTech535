STRATEGY

Why the wheel

The wheel builds on the earlier assignment, with a clear decision at each stage: sell a put when holding cash, sell a covered call when holding shares, and wait while an option is still open. Microsoft is the stock in the price file supplied by Prof. Vestal.

This version uses stock prices to choose strikes and minimum premiums. The earlier PG backtest used option-chain data and different strike-selection rules, so its returns do not measure the performance of this MSFT version.

CASH

Sell a cash-secured put

Start with a strike at or below 95% of the latest available close, rounded down to a $5 increment. Lower the strike if needed so buying 100 shares at that price, plus a $0.65 fee reserve, fits within 90% of cash. Skip the order if that would push the strike below half the stock price.

SHARES

Sell a covered call

With shares held in whole 100-share lots, choose a strike at least 5% above the stock price and no lower than the highest purchase price of the shares. Round up to a $5 increment and sell one call against 100 shares. This cost-basis floor can delay a trade after a price decline.

OPEN OPTION

Wait

Keep one option order or position at a time. Wait if an option is already open, the previous order has not been accounted for, or the inputs are missing. Each order is limited to one contract.

Expiry and limit price

The 21DTE+ rule requests a listed expiry at least 21 calendar days after the order’s trading date. The minimum premium is 0.5% of the stock close, rounded up to the next cent. This is a pricing rule, not a downloaded option quote. The order can remain unfilled if the market does not reach that price, or unresolved if Sanji cannot find the contract.

ACCOUNT RULES

Cash and order history

The starting paper budget is $50,000, set in nightly_config.json. It is the budget for this exercise, not a reported brokerage balance. The first order can use that starting budget while the positions file is still missing.

Before publication, each order is saved in state/order_commitments.json. Running the script again for the same session reuses the same order ID. For a later session, an updated positions file is required before committing more cash or shares.

The script uses the latest completed trading day’s price, allowing a delay of one trading session because the price feed can arrive late. The price date and delay appear above. A longer gap stops new orders.

Positions-file format

The script reads the date, cash and holdings from mkt/positions.json, or positions.json at the root. It checks that the date matches the latest completed session. The expected fields are documented in the input schema. The reader may need adjustment to match the file Prof. Vestal’s system sends back. An unfamiliar format stops new orders.

AUTOMATION
What runs each night


The GitHub Action is scheduled for 10 p.m. New York time. GitHub can start scheduled jobs late, so the script works out the trading dates when it actually runs. It can also be started manually from the Actions tab.


  1. Download the latest copy of my repository, including prices and order history.
  2. Install Python dependencies and run the strategy tests.
  3. Run src/nightly_orders.py to read the inputs and write the order file.
  4. Commit changes to GitHub. If another process updated the repository first, stop so the decision can be rerun with those changes.
  5. Run the Pages workflow to publish the latest files.


The script saves open_orders.json at the repository root as requested in the assignment, under mkt/ to match Prof. Vestal’s order menu, and under docs/ for display here.

SANJI
How this connects to the course system


Prof. Vestal’s server supplies price_history.json to my repository. My job runs after the close and writes the orders. Sanji’s role is to read those orders, work out fills and assignment, and send back updated positions.


Prof. Vestal said in the November 17 class that he was still building that connection. His order menu also says that order resolution is not enabled yet. For now, my script produces the initial order and waits for a positions update before starting another trade.


Using the supplied price file avoids a separate LSEG request. The nightly job therefore needs no LSEG login or running desktop session. GitHub’s built-in job token lets it save the output to my repository.
